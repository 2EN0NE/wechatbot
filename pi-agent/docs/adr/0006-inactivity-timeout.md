# 微信桥超时：不活跃判定，仅通知一次

pi 的 turn 可能在无总时长上限的情况下卡住（无超时的挂起脚本、等待 TUI 权限确认、模型长时间无输出）。桥用「不活跃超时」判定卡住：活动轮次期间，自最后一次活动事件（`message_update` / `tool_execution_*` 等）起超过阈值（默认 180s，可配）仍无进展，就向微信发送一次提示并附上最新流式回复文本；不自动中止。

为什么不用总时长（wall-clock）超时：合法长任务（持续吐日志的构建）会误报。为什么仅通知不自动中止：中止是用户显式动作（stop/esc），误杀「慢但没死」的任务代价更高。为什么每 turn 只通知一次：通知的作用是打破静默，反复刷屏是噪音。

扩展拿不到「等待权限确认」事件——权限弹窗发生在 TUI 层，扩展视角里「等权限」与「思考」「挂起」都表现为「忙 + 无活动事件」，故只能以不活跃为判据。
