# Roadmap

本文档记录 wechatbot 的产品路线图：一个以微信为统一入口的「总控 / 意图 agent」，本地起步、远期演进到 mac 与云端互备。
变更日志见根目录 `CHANGELOG.md`；发布机制见 `.github/workflows/`（tag 触发）。

**当前版本**：`0.1.0`（对应 `CHANGELOG.md` 的 `## v0.1.0` 基线）

---

## 愿景

微信是唯一入口，pi agent 作为「总控 + 意图 agent」：理解用户意图，**按任务特点**调度其他 pi 进程（分工协作）并回收结果；长期能够接受金融交易指令，具备**事务保障**与**交易 ID**（幂等、可追溯、可审计）。部署从本地起步，远期演进到「mac 与云端互备」的高可用架构。

---

## 主题与路线

> 时间远近用 **Now / Next / Later** 表示阶段，不承诺硬日期；主题按「要达成的结果」组织，具体任务落到 issue 管理。

### 1. 安全加固

**目标**：只有被信任的人能驱动 agent；工具执行不越权破坏宿主机与云端资产。

- **Now** — wxid 发送者白名单：入口鉴权，只允许白名单 wxid 触发 turn（当前无鉴权，任何能给 bot 发消息的人都能以宿主权限触发工具执行）。
- **Next** — 敏感指令二次确认：对交易 / 破坏性操作要求显式确认（与「交易与事务保障」主题联动）。
- **Later** — pi-gondolin 沙箱：工具执行隔离（宿主机密钥 / 文件 / 网络），仅当出现「运行不可信代码」需求时引入；它防不住「模型直接说出敏感内容」，不能替代鉴权。

### 2. 稳定性与可观测性

**目标**：本地长跑下桥接不丢消息、不静默卡死；任何时刻都能回答「桥什么状态、队列堆了几条」。**这是当前阶段的主线**——本地稳定性是云端互备、多进程编排、交易等一切后续的前提。

- **Now** — 固化 SDK 层稳定基座并纳入桥接保障：游标持久化、指数退避、session 重登、优雅停止。
- **Now** — 统一状态栏 + 结构化日志持续覆盖（队列计数、轮次状态）。
- **Next** — 崩溃自恢复 + 启动状态回放；对队列堆积 / 轮次停滞的告警可观测化。

### 3. 高可用与云端互备

**目标**：从「单机 mac 长跑」演进到「mac 与云端互备」——mac 为主、云端为备，mac 故障时自动切换到云端，服务不中断。形态暂不定，属长远目标。

- **Later** — 状态外置：游标 / token / 队列持久化到存储（互备切换的前提，状态须能在 mac 与云端之间迁移）。
- **Later** — 密钥管理：云端 secrets 托管，替代环境变量 / 本地文件。
- **Later** — 故障转移：健康检查 + 自动切换（mac 失效 → 云端接管）。

### 4. 多进程编排（跨 pi 进程分工）

**目标**：微信端一句话，总控识别意图并按任务特点分派给其他 pi 进程，结果回收回微信。pi 原生没有 subagent，采用社区框架或自研实现跨进程调度。

- **Next** — 意图识别与路由骨架：总控分流（编码 / 研究 / 交易 / 闲聊…）。
- **Later** — 跨进程调度与结果回收：启动、并行 / 串行编排、上下文回收、失败重试。

### 5. 交易与事务保障

**目标**：能安全地接受并执行金融交易指令，具备幂等、可追溯、可审计。

- **Later** — 交易 ID：幂等去重 + 全链路可追溯。
- **Later** — 事务保障：至少一次 / 精确一次语义，失败补偿与回滚。
- **Later** — 交易指令确认流 + 审计日志（who / when / what / 结果）。

## 版本策略

- 仓库级 changelog 版本与各子包（pi-agent、nodejs、python、golang、rust）的 package 版本是两套独立体系，互不耦合。
- 发版触发：push `v*` tag（现有 `release-binaries.yml` / `publish-*.yml`）。
- 现状：release notes 由 GitHub 自动生成（`softprops/action-gh-release` 的 `generate_release_notes`）。
- 待办（可选）：切换到 CHANGELOG 驱动的 release notes（nano-pi-agent-creator 式，从 `CHANGELOG.md` 提取 `## vX.Y.Z` 段落），需改造 `release-binaries.yml` 的 release 步骤。
